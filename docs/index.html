어떻게 동작하나

  • watsonx Orchestrate(wxO)는 에이전트가 툴을 부르는 곳입니다. LLM은 호출 순서, 재시도, 답변 정리만 맡습니다.
  • watsonx.data intelligence(wxdi)는 데이터 설명서(카탈로그, 용어집)와 Text-to-SQL REST를 제공합니다. SQL을 만들기만 하고 실행하지는 않습니다. SQL을 쓰는 모델은 wxdi 내부의 meta-llama/llama-3-3-70b-instruct(질문과 스키마를 맞추는 임베딩은 granite-embedding-278m-multilingual)이며, 응답의 resource_usage.model_usages에서 확인했습니다. 에이전트의 gpt-oss-120b는 SQL을 쓰지 않고 툴 호출 순서와 답변 정리만 맡습니다.
  • Db2는 데이터가 있는 곳입니다. 만들어진 SQL은 Db2로 직접 실행하며, 조회(SELECT)만 허용합니다.
  • QuickChart(외부 서비스)는 차트 이미지를 그려 주는 곳입니다. make_chart가 차트 값(라벨, 숫자)을 보내고 이미지 주소를 받습니다. 값이 이 서비스로 나가므로 실데이터에는 쓰지 않거나 자체 호스팅이 필요합니다.

툴하는 일연결 대상주요 출력
generate_sql한국어 질문을 Db2 SQL로 바꿉니다. 호출할 때마다 wxdi 카탈로그에서 FK 조인 조건을 읽고(5분 캐시), map_terms가 준 용어 정의(glossary_hints)와 함께 질문 뒤에 Note:로 붙여 Text-to-SQL에 보냅니다. 실행하지는 않습니다.wxdi 카탈로그 + wxdi Text-to-SQL REST (SQL 생성 LLM: Llama 3.3 70B)ok, sql, score, error
run_sqlSELECT 또는 WITH 한 문장만 Db2에서 실행합니다. 최대 200행. 쓰기와 다중 문장은 막습니다.Db2 FIN_DEMO (SSL)columns, rows, row_count, executed_sql, error
map_terms질문 속 업무 용어를 용어집 표준 용어와 컬럼에 연결합니다. 동의어(약정, 잔고 등)도 wxdi 용어집에서 동의어로 연결된 용어를 읽어 같은 표준 용어로 묶고, 용어 정의를 glossary_hints로 돌려줍니다. 날짜별 스냅샷 테이블(BALANCE_DAILY)의 값은 정의에 "여러 날짜를 더하지 말고 가장 최근 기준일만 쓴다"고 적어 두었습니다(코드가 아니라 용어집이 원본). 용어·메타데이터 검색, SQL, Insight 에이전트가 함께 씁니다.wxdi 용어집 (표준 용어 25개 + 동의어 35개 게시)mappings, ambiguous, unmapped, glossary_hints
get_catalog테이블 이름이나 키워드로 컬럼 설명, 키, 개인정보 여부, 외래키를 돌려줍니다.wxdi 프로젝트 자산tables, columns, keys, pii
make_chart조회 결과를 line, bar, pie 차트로 만듭니다. 차트 값(라벨, 숫자)을 외부 서비스 QuickChart에 POST해 짧은 이미지 주소(https)를 받고(실패하면 긴 주소로 대체), 그 주소를 마크다운 이미지로 답변 맨 위에 넣고, 요약, 데이터 표, 용어 매핑, SQL까지 조립해 돌려줍니다. 위젯(user_defined)을 함께 실어서 툴 응답이 그대로 사용자 답변이 되고, Insight 에이전트는 요약, 용어 매핑, SQL을 인자로 넘깁니다. 실패하면 표만 돌려줍니다. 파이는 8개를 넘으면 "기타"로 묶습니다.없음 (Python)성공: 차트 이미지가 든 답변 본문. 실패: fallback_table, error

SQL 품질을 지키는 장치

업무 용어와 조인 경로는 코드에 적지 않고 wxdi가 원본입니다. 툴은 읽어서 전달만 합니다.

  • 용어 정의 → Note: map_terms가 wxdi 용어집에서 읽은 정의(예: 거래대금 = EXECUTIONS.EXEC_AMOUNT)를 질문 뒤에 붙임
  • FK 조인 조건 → Note: generate_sql이 wxdi 카탈로그의 foreign_keys(join_condition)를 읽어 "이 조건으로만 조인하라"고 질문 뒤에 붙임. wxdi 제품은 FK를 LLM에 자동 전달하지 않기 때문입니다
  • 연결 제한: 카탈로그에서 얻은 FIN_DEMO 연결 ID로 스키마 검색 범위를 제한
  • 고정 규칙 5개(instructions): 스키마 인용 규칙, 날짜(어제, 월), 대문자 식별자, 컬럼 한정, 숫자 단위(1억 = 100000000). Db2 문법과 한국어 표현만 두었습니다
  • fix_qualifiers: Db2가 거부하는 컬럼 한정 방식을 "FIN_DEMO"."T"."C" 형태로 자동 교정. 테이블 목록은 카탈로그에서 읽음

예상 질문

막(질문 종류)별로 잘 답하는 질문만 골랐습니다. 이런 질문을 할 수 있고, 이런 답이 나와야 하며, 실제로 이런 답이 나오는 것을 확인했습니다. 2026-11-20에 홈 화면의 Supervisor 에이전트에 직접 물어 확인한 결과이고, 에이전트 응답은 실행마다 조금 다를 수 있습니다. 질문 문구가 달라지면 결과가 달라질 수 있으니 아래 문구 그대로 쓰는 것을 권장합니다. 안 되는 질문까지 포함한 전체 목록은 질문별 검증 현황에 있습니다.

Text-to-SQL 평가 (골든)

SQL 정답이 있는 질문만 모은 골든 세트(shared/spec/golden/golden.json)로 Text-to-SQL이 얼마나 맞게 SQL을 만드는지 잰 결과입니다. 아래 내용은 평가 스크립트(eval_golden.py --export)가 저장한 실제 실행 결과입니다.

  • 평가 경로: 질문 → map_terms(동의어를 표준 용어로 바꾸고 용어 정의 전달) → generate_sql(카탈로그 FK와 용어 정의를 Note로 붙여 wxdi Text-to-SQL 호출) → Db2 실행. 에이전트 LLM(gpt-oss-120b)의 판단은 빠지고 SQL 생성 툴과 같은 코드 경로만 잽니다. 평가 대상은 wxdi 내부 모델(meta-llama/llama-3-3-70b-instruct)이 쓴 SQL입니다.
  • 채점: 골든 SQL과 생성 SQL을 Db2에서 실행해 결과 값을 비교합니다. 행 수가 같고 골든의 각 행 값이 생성 결과에 모두 들어 있으면 통과이며, 컬럼 순서와 이름, 추가 컬럼, SQL 문장 모양은 보지 않습니다. 실행 오류와 불일치는 실패입니다.
  • 반복: 같은 질문을 3번씩 생성합니다. 생성기가 매번 다른 SQL을 낼 수 있어서입니다.
  • 개인정보: 결과의 고객 이름은 가려서 표시합니다.

eval_results.js를 불러오지 못했습니다.

시나리오 질문 목록(shared/spec/questions.md)과 같은 번호입니다. 현재 구성에서 다시 확인한 결과이며, 안 되는 질문도 함께 표시합니다. 오른쪽 메모는 확인 방법입니다.

  • 골든 평가: SQL 정답이 있는 10문항(S1-01, S1-02, S1-03, S2-01, S2-02, S2-04, S2-05, S3-03, S3-04, S5-02)을 3번씩 생성해, 생성한 SQL과 정답 SQL을 Db2에서 실행한 결과 값을 비교합니다. SQL 문장이 달라도 값이 같으면 정답입니다. 가장 최근 평가는 27/30 (90%)이고, 질문별 골든 SQL과 생성 SQL, 결과는 Text-to-SQL 평가 탭에 있습니다. "골든 2/3"은 3회 중 맞은 횟수입니다.
  • 표현에 민감한 질문: S3-03과 S5-02는 이 표에 골든 평가에 쓴 문구로 적었습니다. 같은 뜻의 다른 문구("종목별 거래대금 순위를 섹터 내에서 매겨줘", "한도의 80%를 넘긴 데스크가 있어?")로 물으면 전체 순위가 나오거나 "없음"이 나온 적이 있어 '불안정'으로 표시했습니다.
  • 골든에 없는 질문: SQL 정답이 없는 되묻기, 대화, 차트 질문과 정답을 정하지 않은 복합 질의는 에이전트에 직접 물어 확인했습니다.
  • 골든 구성이 바뀌었습니다: 이전 점수(10문항, 27/30)는 번호와 문항이 달라 직접 비교할 수 없습니다.
